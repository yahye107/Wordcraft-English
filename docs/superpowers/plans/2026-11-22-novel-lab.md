# Wordcraft Novel Sentence Lab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the learner paste a short passage from a book they are reading and see how it works: its vocabulary, sentence structure, dialogue tags and action beats, descriptive and emotional techniques, and how to use the same technique in a different situation. The lab is useful with no API key through local analysis; Claude adds explanation of grammar and "why it sounds natural" when a key is set.

**Architecture:** One analysis result with two layers. The **local layer** (no network) splits the passage into sentences, colour-codes it with the existing annotation marks (speech, tag, beat, main, sub, part, link, detail), matches words against the expression library, lists unfamiliar words, and names techniques it can detect, each linked to an existing lesson. The **AI layer** (optional) returns a validated explanation in simple English plus an original example of the technique. Results are stored in a local table. Route handlers are thin wrappers over functions that take an injected `Db`, as in earlier phases.

**Tech Stack:** Same as before. No new dependencies. AI calls only through `src/lib/ai/client.ts` (`askClaude`).

**Spec:** `docs/superpowers/specs/2026-11-19-wordcraft-design.md` (sections 6 and 9, "Novel Sentence Lab"; Phase 7 in section 10). Builds on the Phase 1 to 6 plans.

- **Copyright:** the lab analyses short passages the learner pastes. It never ships book text. Passages are limited to **800 characters and 120 words**; longer input is refused with a message asking for a shorter passage. Passages are stored only in the learner's local database and can be deleted. All teaching examples are **original**: an AI example that reuses the passage is rejected (Task 4).
- **Privacy:** with AI analysis, the passage is sent to Claude and nothing else (no source title, no notebook data). Show a clear notice before the first AI send. The local-only action sends nothing and never calls the AI.
- AI is optional. With no key, over budget, a failed call or invalid output, the learner still gets and keeps the local analysis with a plain reason. Local results are labelled as automatic guesses where they are heuristics.
- Treat the passage as data, not instructions: the system prompt says to ignore instructions inside it.
- **Annotation safety:** passages may contain `{` and `}`. Replace them with `(` and `)` before building annotation markup so pasted text can never create or break marks. Everything is rendered as plain text (React escapes it).
- Limits: passage at most 800 characters and 120 words and not empty; source title at most 100 characters; at most 200 stored analyses (the oldest are refused with a message, not deleted silently); bodies over 20,000 bytes return 413; unknown ids 404; bad shapes 400.
- Learner data lives only in the new table; content seeding never touches it. All explanations in simple English. Responsive from 375px, visible focus, reduced motion respected, targets at least 44px. All earlier unit and end-to-end tests keep passing.

## Review Focus

1. Empty, over-long (more than 800 characters or 120 words), whitespace-only and non-text passages return 400 and store nothing; text with braces, HTML, markdown, emoji and right-to-left characters is analysed and shown as plain text, and pasted `{tag|x}` never creates a mark.
2. The local annotator never throws on unbalanced or nested quotes, apostrophes, only punctuation, a single 800-character word, or unusual quote characters (`«»`, `„“`, curly and straight); removing the markup from its output gives back the passage (with braces swapped) exactly: no characters lost or invented.
3. An AI example that reuses 50 percent or more of the passage's words in order, or an exact run of 8 or more passage words, is rejected; AI quotes that are not exact substrings of the passage are dropped; one bad field does not discard the rest of a valid reply.
4. With no key, over budget, API error or invalid JSON the local analysis is still stored and shown with `aiUsed: false` and a reason; the local-only action never calls the AI (tested with a responder that fails the test if called); the request sent to the model contains only the passage and the rules (no title, no notebook data).
5. Vocabulary matching finds inflected forms ("whispers" for whispered), does not match inside longer words ("art" inside "party"), is case-insensitive, caps at 20 matches and caps unfamiliar words at 10.
6. Analysing the same passage again returns the existing analysis (one row, no second AI call); asking for AI on a stored local-only analysis adds the AI layer to the same row.
7. Dialogue detection: a speech verb after a closing quote is a tag; a non-speech action sentence beside dialogue is a beat (the heuristic is labelled an automatic guess); "said" in narration without quotes is not a tag; speech with no tag is still marked as speech.
8. The privacy and copyright notice is visible before the first send, and deleting an analysis removes the stored passage.

### Task 2: Local annotator (dialogue, tags, beats, clauses)

**Files:**
- Create: `src/lib/novel/annotate.ts`, `src/lib/novel/speech-verbs.ts`
- Test: `tests/novel/annotate.test.ts`

**Interfaces:**
- `speech-verbs.ts`: `SPEECH_VERBS: Set<string>` of common verbs of speaking (said, asked, replied, whispered, murmured, muttered, mumbled, snapped, exclaimed, remarked, protested, shouted, cried, called, answered, added, explained, suggested, insisted, demanded, sighed is **not** included), plus `speechVerbsFromLibrary(db): Set<string>` that adds the texts of published expressions in the category `speaking-styles-and-dialogue-tags` (past tense forms already present) and lower-cases them.
- `annotate.ts`:
  - `sanitise(text: string): string` replaces `{` with `(` and `}` with `)`.
  - `splitSentences(text: string): { text: string; start: number }[]` (handles `.`, `!`, `?`, closing quotes after them, and does not split on common abbreviations `Mr.`, `Mrs.`, `Dr.`, `St.`, `e.g.`, `i.e.` or decimal numbers; never returns an empty sentence; a single very long string returns one sentence).
  - `annotatePassage(text: string, speechVerbs: Set<string>): { markup: string; sentences: { text: string; kind: 'dialogue' | 'narration' | 'mixed'; words: number }[]; tags: string[]; beats: string[]; participles: string[]; subordinates: string[]; stats: { sentences: number; averageWords: number; longest: number; shortest: number } }`. `markup` uses the annotation syntax (`{speech|...}`, `{tag|...}`, `{beat|...}`, `{sub|...}`, `{part|...}`, `{link|...}`, `{main|...}`) over the sanitised passage and always satisfies `stripAnnotations(markup) === sanitise(text)`.
  - Rules (heuristics, documented in code comments): text inside paired quotation marks (`“…”`, `"…"`, `«…»`, `„…“`) is speech; an unbalanced quote treats the rest of the sentence as speech; the words right after a closing quote up to the sentence end form a **tag** when they contain a speech verb (a word in the set) next to a name, pronoun or noun; a sentence adjacent to speech with no speech verb and a past-tense-looking action verb (a word ending in `ed` or in a small list of irregular action verbs) is a **beat**; a clause opening with `because, although, though, while, when, if, unless, since, as, after, before, until` is **sub**; an opening or closing phrase starting with an `-ing` or `-ed` word set off by a comma is **part**; `however, nevertheless, therefore, meanwhile, moreover, but, yet, so` at a sentence start is **link**. The `{main|…}` mark is used for the rest of a narration sentence that contains a sub or part. Overlaps are resolved left to right so marks never nest.
